# Loupedeck Claude Session Board — Design

## Intent
Use the Loupedeck Live S as a physical dashboard for all open Claude Code
sessions on this Linux PC (Ubuntu, GNOME Wayland, Tilix). Glance at it to see
which session is working, which needs you, and which is done; press a key to
jump straight to that Tilix tab.

## Goals
- One touch key per Claude session, colored by status, labeled with the project.
- Press a key → Tilix focuses that exact terminal (window + tab + pane).
- Updates live, with no manual setup per session (works for every `claude` started in Tilix).
- Starts automatically at login.

## Non-goals
- Controlling Claude from the device (sending prompts, approving permissions).
- Non-Tilix terminals jumping (they are shown, but pressing only flashes the key).
- Windows/macOS support, Loupedeck's official software.

## Anti-goals
- Hooks must never slow down or break Claude: fire-and-forget, 1s timeout, failures ignored.
- No stale ghosts: closed sessions disappear on their own.

## Approaches
1. **Node.js daemon + `loupedeck` npm library** — maintained, supports Live S
   (touch keys, dials, buttons, LEDs). *Chosen by user.*
2. Python daemon with hand-written serial protocol — no maintained library, more risk, no benefit.

## Verified facts
- Device: Loupedeck Live S at `/dev/ttyACM0` (USB 2ec2:0006), group `dialout`; a normal user is usually not in `dialout` → needs a udev rule.
- Tilix exposes D-Bus action `activate-terminal` taking a terminal UUID; each terminal has `$TILIX_ID`.
  `gdbus call --session --dest com.gexperts.Tilix --object-path /com/gexperts/Tilix --method org.gtk.Actions.Activate activate-terminal "[<'$ID'>]" "{}"` succeeds.
  Open risk: whether GNOME Wayland raises the window or only shows "Tilix is ready". Fallback: tiny GNOME Shell extension.

## Design
**Hooks** (added to `~/.claude/settings.json`) call one script, `hook.sh <event>`,
which POSTs `{event, session_id, cwd, tilix_id, pid=$PPID}` + hook stdin JSON to
`http://127.0.0.1:47800/event` via `curl --max-time 1`, always exits 0.

| Hook event | Status |
|---|---|
| SessionStart | idle (registered) |
| UserPromptSubmit, PreToolUse | working |
| Notification | waiting (needs you) |
| Stop | done |
| SessionEnd | removed |

**Daemon** (this repository, Node ≥ 20):
- HTTP server on 127.0.0.1:47800; in-memory session list, persisted to
  `~/.local/state/loupedeck-claude/sessions.json` so restarts keep the board.
- Every 5s prunes sessions whose Claude pid is gone.
- Reconnects automatically if the Loupedeck is unplugged/replugged.

**Display** (15 keys, 90×90 each):
- Key = project folder name + status word + time in that status.
- Colors: working = blue, waiting = amber (pulsing), done = green, idle = dark gray.
- Order: by session start; stable positions.
- Pressing a key: focus that terminal; a "done" session then becomes idle (seen).
- More than 15 sessions: left dial pages. Right dial: brightness.
- Round button 1: jump to the session that has waited longest for you.

**Install** (`install.sh`): udev rule (one sudo), `npm install`, systemd user
service `loupedeck-claude.service`, merge hooks into settings.json (backup first).

## Left to the builder
Fonts/exact visual styling, internal module layout, test approach.

# Addendum (2026-11-22): stat keys, action buttons, kill switch

Approved by user. Button IDs verified by logging presses.

| Button | Position | Action | LED |
|---|---|---|---|
| 0 | under the dials | **Kill all**: hold 2 s (keys count down in red, release cancels), then SIGTERM every Claude/Codex session process on the board (SIGKILL after 5 s if still alive). Tabs stay open at a shell prompt. Codex app-server is not touched. Re-checks `/proc/<pid>/comm` is claude/codex before signalling. | red |
| 1 | top right | New Tilix tab running `claude` (then a shell when it exits) | Claude orange |
| 2 | middle right | New Tilix tab running `codex` | Codex blue |
| 3 | bottom right | Jump to longest-waiting session (moved from button 0) | amber when someone waits |

New tabs open in the folder of the last session jumped to, else `$HOME`, via
`tilix -a app-new-session -w DIR -e "$SHELL -ic '<agent>; exec $SHELL'"` (verified).

**Stat keys** fill free keys from the bottom-right corner backwards and never displace sessions:
14 Right now (working/needs you/done/idle counts), 13 Today (prompts sent, tasks finished),
12 Tokens today (Claude, Codex: fresh input + output, cache reads excluded),
11 Longest task running (name + time), 10 Waited on you today (time spent amber).
Daily counters reset at local midnight and persist in the state file.
Token sources: `~/.claude/projects/**/*.jsonl` (assistant `message.usage`, deduped by message id) and
`~/.codex/sessions/YYYY/MM/DD/*.jsonl` (`token_count.last_token_usage`), scanned incrementally every 30 s.
